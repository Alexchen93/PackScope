# 操作與驗證說明

PackScope 使用對應套件管理器執行安裝、更新和移除，系統權限操作透過 Ubuntu polkit / pkexec 授權。指令以參數陣列執行，不使用 shell 串接；密碼由系統授權代理處理。APT 安裝、更新及移除在確認前會以無鎖定的唯讀模擬顯示套件變更；模擬無法完成時會明確警告並要求使用者再次確認。模擬根據目前本機套件清單，不能保證實際執行結果完全相同。

APT、Snap、Flatpak、pipx、npm、Cargo 操作的命令建構和介面背景流程已以模擬呼叫進行自動測試；APT 變更預覽也有解析與失敗回退測試。AppImage 的安裝、桌面捷徑及移至垃圾桶已在暫存使用者目錄中實測。Flatpak 使用自建的本機測試來源與獨立使用者目錄，實測安裝、更新至新提交及移除。原生 polkit 密碼視窗與圖形介面的完整流程尚未進行端到端測試；待執行步驟見 [`../tests/vm/desktop-checklist.md`](../tests/vm/desktop-checklist.md)。

2026-10-31 曾以 Ubuntu 24.04 隔離虛擬機及測試套件驗證 APT 本身的安裝、升級、移除和依賴模擬；該測試不是 PackScope 圖形介面與授權流程的端到端驗證，腳本保存在 `tests/vm/user-data`。

0.2.0 開發版另在 Ubuntu 24.04 虛擬機中使用 PackScope 的操作程式碼，實際安裝、升級及移除自建 APT 測試套件，安裝與移除自建 Snap 測試套件，並將官方 Snap `bare` 由修訂版 4 升級至 5。虛擬機以 root 執行並用測試替身取代 pkexec，因此不代表已驗證桌面授權視窗。DEB 安裝檔的檔案和捷徑亦在虛擬機中檢查；由於測試映像缺少 GUI 依賴，未在虛擬機中完成 GUI 啟動驗證。

套件管理器作業沒有被 PackScope 強制逾時或終止；中斷 APT/dpkg 可能留下未完成的交易。若長時間沒有輸出，介面會提醒使用者檢查授權視窗、網路及輸出紀錄。作業期間要求關閉視窗時，程式會延後關閉並說明可最小化等待；這不能防止使用者從作業系統強制終止整個程式。

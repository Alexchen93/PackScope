# Ubuntu 桌面與 polkit 端到端驗證清單

此清單補足 `user-data` 的 cloud VM 套件測試；它要求 Ubuntu Desktop、登入中的一般使用者、圖形化 polkit 授權代理與實際 PackScope 視窗。自動化單元測試或以 root 執行的套件測試不能取代此流程。

## 隔離與準備

- [ ] 建立可還原的 Ubuntu 24.04 Desktop VM 快照；不要在日常使用的主機測試。
- [ ] 以一般桌面使用者登入，確認不是 root，且授權提示能顯示在桌面上。
- [ ] 建置並安裝本次待驗證的 PackScope DEB；記錄 Git commit、DEB 檔名及 SHA-256。
- [ ] 確認 VM 可還原快照，並準備只供測試的 APT 套件。需要驗證相依項目時，使用 VM 內的本機測試來源，不使用真實重要軟體。
- [ ] 測試前記錄測試套件狀態：`dpkg-query -W -f='${db:Status-Status} ${Version}\n' <套件 ID>`。

## APT 變更預覽與授權

- [ ] 從應用程式選單啟動 PackScope；掃描完成後確認來源狀態及錯誤提示可見。
- [ ] 安裝測試 `.deb`。在確認視窗中展開「顯示詳細資料」，確認模擬的安裝／升級／移除套件與 APT 摘要符合預期。
- [ ] 選「否」；確認沒有出現授權視窗，且測試套件狀態未改變。
- [ ] 再執行安裝並確認。以一般使用者流程觸發原生 polkit 授權視窗，完成授權後確認安裝結果、輸出紀錄及清單重新掃描。
- [ ] 再執行一次需要授權的 APT 操作，在 polkit 視窗取消或拒絕；確認操作顯示未完成、介面控制項恢復，且套件狀態未意外改變。
- [ ] 選取多個 APT 更新項目；確認它們由同一次模擬產生合併預覽，並可在詳細資料中查看完整變更清單。
- [ ] 測試模擬失敗的情況（例如在快照中使用沒有候選版本的測試套件）。確認畫面明確警告「無法預覽」、詳細資料列出原因，且預設選項為「否」。只有在安全測試套件上，才可另行確認失敗預覽後的操作流程。
- [ ] 對非 APT 來源確認畫面應說明該來源未納入 APT 模擬，不得將 APT 結果呈現為其他管理器的預覽。

## 長時間作業與關閉視窗

- [ ] 在可安全等待的測試作業中確認輸出區會即時更新，作業期間主要操作按鈕不可重複觸發。
- [ ] 在作業期間嘗試關閉視窗；確認關閉被延後，狀態及輸出區說明不能強制中止套件管理器，並提示可最小化視窗及檢查授權視窗／網路。
- [ ] 若作業超過 60 秒沒有新輸出，確認狀態及輸出紀錄顯示無輸出提醒。不要用強制終止來測試此情境。
- [ ] 最小化後返回視窗，確認作業結果仍可見；作業結束後確認可正常關閉程式。

## 完成與記錄

- [ ] 以 `dpkg-query` 驗證安裝、升級或移除結果；查看 APT／dpkg 狀態沒有未完成設定。
- [ ] 使用 VM 快照還原測試環境，不在主機清理測試套件。
- [ ] 記錄每個項目的通過／失敗、Ubuntu 映像與桌面工作階段、PackScope commit、DEB SHA-256、polkit 結果，以及必要的截圖／輸出紀錄。

> 本清單是待執行的驗收流程；只有完成並記錄後，才能宣稱原生桌面與 polkit 端到端流程已驗證。PackScope 不會在長時間套件操作期間強制終止程序，以避免破壞 APT/dpkg 的交易狀態。
